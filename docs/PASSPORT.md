# Паспорт демо 1: металлопрокат и металлоконструкции

Версия от 31.10.2026. Этот файл — единственный источник правды по демке. Если в чате что-то решили иначе — обновляем файл в репозитории (`docs/PASSPORT.md`).

## 1. Зачем эта демка
Демо-сайт веб-студии из двух человек. Показываем владельцам производств и B2B-поставщиков, как выглядит сайт, который приносит заявки и запросы КП. Отправляем ссылку во втором письме холодной цепочки.

Демка должна за 30 секунд показать:
- красивый, «дорогой», но деловой сайт производства;
- что мы понимаем B2B: не корзина с оплатой картой, а «Список для КП» → КП → счёт → отгрузка;
- сложный функционал: каталог с фильтрами, калькулятор металла, личный кабинет закупщика;
- отличную мобильную версию и скорость.

Компания вымышленная. В подвале: «Демо-проект студии [название]. Компания и данные вымышлены». Демку не называем реальным кейсом.

## 2. Компания (вымышленная)
- Металлобаза + цех металлоконструкций. Название придумываем в первом чате и проверяем поиском, что крупной реальной компании с таким именем нет.
- Город: любой крупный промышленный (например, Екатеринбург). Адрес и реквизиты условные.
- Клиенты: строительные компании, подрядчики, заводы, снабженцы.
- Цифры для главной (условные): лет на рынке, тонн на складе, позиций, срок отгрузки, объектов.

## 3. Аудитория и сценарии
1. **Снабженец**: ищет позицию по ГОСТу и размеру → фильтр → карточка → считает вес/цену → добавляет в Список для КП → отправляет запрос с реквизитами.
2. **Прораб / инженер**: нужна металлоконструкция → страница «Металлоконструкции» → загружает чертёж → получает расчёт.
3. **Постоянный клиент**: заходит в ЛК → смотрит статус заказа → скачивает счёт/УПД → «Повторить заказ».
4. **Директор**: листает главную и «О производстве» → проверяет надёжность (цех, оборудование, сертификаты, объекты).

## 5. Функционал на заглушках (делаем мы)
Всё работает в браузере без сервера.
- Данные: `data/*.json` (товары, категории, заказы, документы, пользователь).
- Состояние: Zustand + localStorage (список КП, избранное, «вход»). Каждое обращение к localStorage в try/catch.
- **Все обращения к «серверу» — только через `lib/api.ts`** (функции `getProducts`, `sendKpRequest`, `login`, `getOrders`, `uploadDrawing` и т. д.). Сейчас внутри задержка 600 мс и тестовые данные. Программист потом меняет только этот файл.
- Калькулятор: вес = масса 1 м × длина × количество; цена = вес / 1000 × цена за тонну. Для листа — по площади и толщине.
- Статусы запроса КП: отправлен → в работе → КП готово → счёт выставлен.
- Статусы заказа: оплачен → в производстве → готов к отгрузке → отгружен.
- PDF документов: 2–3 статичных файла-образца в `public/docs`.

## 6. Что потом делает программист
Авторизация, база данных, отправка заявок и чертежей в Telegram/почту, админка менеджера (заявки, статусы, загрузка КП и счетов), при желании выгрузка из 1С. Для него в репозитории `docs/HANDOFF.md`: какие функции в `lib/api.ts` и что они должны возвращать.

## 7. Данные каталога
Категории: арматура, труба профильная, труба круглая, лист г/к и х/к, уголок, швеллер, балка двутавровая, круг, полоса, сетка.
По 5–8 позиций в категории (всего 50–70). Поля товара:
`id, slug, category, name, gost, steelGrade, size (объект), weightPerMeter, pricePerTon, unit, length, inStock, image`.
Цены условные, но правдоподобные.

## 8. Стек
- Next.js (App Router) + TypeScript, статичный экспорт (`output: 'export'`, `images.unoptimized`, `basePath` под GitHub Pages).
- Стили: CSS Modules или Tailwind на дизайн-токенах.
- Zustand для состояния.
- 3D: только на главной, загружается лениво (`dynamic`, `ssr: false`) после первого экрана; на слабых телефонах и при `prefers-reduced-motion` — статичная картинка. Вес 3D-модели до ~1–1,5 МБ.
- Иконки: одна библиотека (Lucide или Phosphor), без эмодзи.
- Деплой: GitHub Actions → GitHub Pages.

## 9. Дизайн
- Направление, референсы, цвета и шрифты выбирает дизайнер в первом чате проекта. Итог фиксируется в `docs/DESIGN.md` и в токенах (CSS-переменные).
- Деловой, «промышленный», дорогой. Ориентир — сайты сильных студий для B2B, а не шаблоны.
- Запрещено: фиолетовые градиенты, неоновое свечение, эмодзи вместо иконок, ряды одинаковых карточек с иконкой сверху, стоковые улыбающиеся люди в касках.
- Анимации сдержанные: появление блоков, hover, переходы. Никакого скролл-цирка.
- Шрифты с кириллицей.

## 10. Критерии готовности
- Все страницы из карты есть и связаны навигацией.
- Сценарии 1–3 проходятся целиком на телефоне и на компьютере.
- Мобильная версия проверена на ширине 360 px: нет горизонтального скролла, таблицы ТТХ не вылезают.
- Lighthouse (мобильный): производительность ≥ 85 на главной, ≥ 90 на остальных.
- Нет битых ссылок, есть 404, есть политика ПДн.
- Демка открывается по ссылке GitHub Pages.
- В `docs/PROGRESS.md` отмечено, что готово.
